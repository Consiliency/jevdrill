# EXPERIMENT interfaces

Portable v1 recovery bundles do not carry the experiment reservation ledger or dispatch identities. Import therefore blocks new experiment admissions in the restored project/workspace, including after restart; existing execution records can still be inspected or canceled. Recovery does not replenish or reconcile a grant. New execution requires a separately reconciled authority and storage boundary.

BAML owns the additive proposal, authorization, readiness, execution, calibration and policy contracts. Python and Node use the same generated strict schemas. A proposal cannot declare authority or host acceptance. Optional generated development calls require an explicitly configured credential callback; defaults dispatch no work.

`Experiments` validates authoritative task/decision/discovery lineage before storing proposals or recurrence. Equivalent configurations deduplicate across fresh task/plan identities while preserving assignment probabilities and configuration changes. Versioned priority reflects recurrence and declared interests; default one background comparison/two candidates grants no execution authority. Resolved experiment settings and every declared grant scope field independently gate admission and dispatch. Project/workspace reservations aggregate across producers, survive daily rollover, deletion and uncertain acknowledgments, and never refund from small bills.

Trusted adapters implement prepare/start/poll/cancel. `DevelopmentRunner` has explicit deferred/internal and immediate/harness-assisted modes; both use durable dispatch tokens, exclusive process custody and the same bounded BAML transport and restricted evaluation. Poll never starts work. Expired/revoked settings, changed source/context/profile/guidance and deletion prevent later calls. Cancellation persists before start, scrubs retained task content and waits for verified cleanup. Lost workers retain reservations and never repeat uncertain provider calls.

Internal code requires the inspected immutable Linux image. It has no host mounts, sockets, credentials or network, runs as an unprivileged user with CPU/memory/process/output bounds, and has a container-owned absolute deadline. Native Darwin and Windows explicitly disable internal execution. The current adapter supports bounded implementation, structured review and documentation tasks; it does not claim to grade arbitrary prose. Input request size is at most8KiB, separately from full documented provider-context cost reservations and hard output limits.

`RecordedPolicyEvidence` freezes authoritative source membership, plans, dataset/evaluator/rubric revisions and exposure history. Durable exposure precedes grading anonymous artifacts by a separately configured independent grader. Missing outcomes remain unknown; actual failed outputs can establish critical regressions. Preference never substitutes for acceptance. `PolicyLifecycle` requires independent promotion authority for a pinned, capped task-group candidate ordering. Feasibility, constraints, permissions, required guidance and budgets retain precedence. Supporting-source deletion/opt-out makes only dependent versions stale; fallback requires a currently verified previous version or returns non-ready.

Installed CLI commands are `experiment`, `experiment-execution`, `policy` and `policy-lifecycle`. Their default application has no execution, grading or promotion authority. The public development protocol exposes its tasks explicitly and leaves all policy/release holdouts untouched.
