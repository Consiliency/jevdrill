# EXPERIMENT interfaces

Portable v1 recovery bundles do not carry the experiment reservation ledger or dispatch identities. Import therefore blocks new experiment admissions in the restored project/workspace, including after restart; existing execution records can still be inspected or canceled. Recovery does not replenish or reconcile a grant. Nothing in the product lifts that block: new execution in that project/workspace needs another storage file and a separately reconciled authority.

BAML owns the additive proposal, authorization, readiness, execution, calibration and policy contracts. Python and Node use the same generated strict schemas. A proposal cannot declare authority or host acceptance. Optional generated development calls require an explicitly configured credential callback; defaults dispatch no work.

Application rejects new injected task/discovery judgment calls with explicit spending ceilings. Their separately configured study allowance does not authorize a narrower request ceiling. DevelopmentJudge's pinned model and the supported token counter are checked against each request before any call; request-bound injected pricing support is deferred.

`Experiments` validates authoritative task/decision/discovery lineage before storing proposals or recurrence. Equivalent configurations deduplicate across fresh task/plan identities while preserving assignment probabilities and configuration changes. Versioned priority reflects recurrence and declared interests. A proposal states its own limits (at least two candidates and a concurrency of at least one); none is supplied by default, and recording a proposal grants no execution authority. Resolved experiment settings and every declared grant scope field independently gate admission and dispatch. Project/workspace reservations aggregate across producers, survive daily rollover, deletion and uncertain acknowledgments, and never refund from small bills.

Trusted adapters implement prepare/start/poll/cancel. `DevelopmentRunner` has explicit deferred/internal and immediate/harness-assisted modes; both use durable dispatch tokens, exclusive process custody and the same bounded BAML transport and restricted evaluation. Poll never starts work. Expired/revoked settings, changed source/context/profile/guidance and deletion prevent later calls. Direct deletion and imported task tombstones both persist experiment cancellation and remove proposals; processing cancellation scrubs retained worker records, securely overwrites SQLite content and compacts previously freed pages. Cleanup remains required before cancellation is complete. Lost workers retain reservations and never repeat uncertain provider calls.

Internal code runs in a local Linux image that the host names by its `sha256:` ID. The runtime checks only the form of that ID and never pulls the image; inspecting the image is the host's responsibility. The container is started with no host mounts, no host sockets, no credentials passed in and no network, as an unprivileged user with CPU, memory and process limits. Its output is read up to 64 KiB, and it kills itself at its deadline, which is an absolute time for a named run. Native Darwin and Windows explicitly disable internal execution. The current adapter supports bounded implementation, structured review and documentation tasks; it does not claim to grade arbitrary prose. The serialized provider request is at most 8 KiB. Separately, each candidate reserves cost from its configured input and output token limits and rates, and for the two pinned GPT-4.1 mini and nano revisions the input limit must be the full documented context. Hard output limits apply as well.

`RecordedPolicyEvidence` binds authoritative source membership, plans and dataset/evaluator/rubric revisions to the frozen protocol, and checks external and local exposure history again each time it builds an evidence snapshot. Durable exposure precedes grading anonymous artifacts by a separately configured independent grader. Missing outcomes remain unknown; actual failed outputs can establish critical regressions. Preference never substitutes for acceptance. `PolicyLifecycle` requires independent promotion authority for a pinned, capped task-group candidate ordering. Feasibility, constraints, permissions, required guidance and budgets retain precedence. Supporting-source deletion/opt-out makes only dependent versions stale; fallback requires a currently verified previous version or returns non-ready.

Installed CLI commands are `experiment`, `experiment-execution`, `policy` and `policy-lifecycle`. Their default application has no execution, grading or promotion authority. The public development protocol exposes its tasks explicitly and leaves all policy/release holdouts untouched.
